# Архітектура Croatia News Bot

Стан на 31.10.2026 — версія з PR #14 (R-11: стоп-слова без хибних спрацювань). Номери рядків — у `news_bot.py`; після змін коду їх треба оновити.

## 2. Один запуск: покроково

### 2.0 `main()` (р. 2105)
Перевіряє `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `GEMINI_API_KEY` → створює клієнт Gemini → `scrape_feeds()` → `refresh_backlog_stats()` → `process_backlog()`. У `finally`: обрізка історій до 1000 рядків, запис `analytics.json`, звіт адміну (лише якщо щось опубліковано або є помилки). **Код виходу 1 — лише при критичній помилці** (виняток в основному циклі, не вдалося зберегти стан чи аналітику). Некритичні помилки (одна новина не пройшла перевірку, одне джерело чи один пост не вдались) рахуються в `errors_count` і видні у звіті адміну, але запуск лишається зеленим. Файли стану комітяться в будь-якому разі (§6).

### 2.1 Збір: `scrape_feeds()` (р. 1652)
- Для кожного джерела з `feeds.json`: завантаження через `cloudscraper` (обхід Cloudflare), `feedparser`, перші **15** записів. Помилка або **порожня стрічка** (0 записів, напр. HTML замість RSS) → помилка джерела: `stats["source_errors"]`, рядок «🔴 Недоступні джерела» у звіті. Після запуску `check_source_health()` (р. 503) порівнює з `analytics.json`: 3-й невдалий запуск поспіль → алерт «🔴 Джерело не працює…» (один раз), перший успішний після ≥ 3 збоїв → «✅ Джерело знову працює» (`SOURCE_ALERT_AFTER_RUNS`; у `DRY_RUN` — без алертів).
- Відкидає: уже в історії URL/заголовків або в беклозі; **уже відхилені фільтром за останні 24 год** (`rejected_news.json`, `load_rejected()` — за URL або заголовком; у звіті «з них відхилені фільтром раніше»; D-25: раніше відхилена новина поверталась з RSS щозапуску й рано чи пізно проходила фільтр — дублі); старші за `MAX_AGE_SECONDS` (12 год); з тегами RSS `sport`, `lifestyle`, `magazin` тощо.
- Якщо опис коротший за 200 символів або обірваний — `fetch_full_article_text()` (р. 722) тягне абзаци зі сторінки (до 3500 символів).
- `quality_rejection_reason()` (р. 801; `is_quality_article()` — обгортка): URL-категорії, `SPORTS_PATTERN`, `AD_PATTERN`, `LEGACY_UNWANTED_KEYWORDS`, довжина заголовка, «!!!», КАПС > 40 %. Повертає, **яке правило** спрацювало (`foto`, `oglasio`, `URL /sport/`, `тег RSS sport`, `КАПС у заголовку`…) — у звіті «Відсіяно кодом: 15 (sportaš 5, derbi 3…)». Кожен такий заголовок пишеться в лог Actions («Відсіяно кодом [правило]: заголовок»), до 20 на запуск — в `analytics.json` (`rejected_by_code_examples`) і в звіт фільтра `DRY_RUN`. Стоп-слова (R-11, 31.10): `sport`/`спорт` — лише іменники (прикметники `sportska`, `спортивний` не відсіюються); реклама — лише явні позначки (`oglas`, `oglasi`, `mali oglasi`, `plaćeni oglas`, `promo`, `PR članak`, `sponzor…`); `foto`, `video`, `bodovi` прибрано.
- Фото — `extract_image_urls()` (р. 701): `media_content` і `enclosures`, без webp/avif/svg, до 10.
- Беклог зберігається атомарно з резервною копією `.bak` (`save_backlog()`, р. 313).

### 2.2 Відбір і публікація: `process_backlog()` (р. 1862)
1. Прибирає з беклогу вже опубліковане; пропускає новини з `retry_after` у майбутньому.
2. Кандидати (до `MAX_CANDIDATES_PER_FILTER` = 25): спершу «український пріоритет» (`UKRAINE_KEYWORDS` — `ukrajin`, `dijaspor`, `zelensk`, `kijev`, `odesa`, `izbjeglic`, тимчасовий захист, директива 2001; `migrant`, `humanitar` прибрано 31.10, R-12; р. 1522), далі по колу між джерелами у випадковому порядку.
3. `deduplicate_news()` (р. 1081) — **редакторський промпт** (корінна подія → кластер дублів → порівняння з 75 останніми заголовками історії → стоп-теми → тематика: Задар, Хорватія, Україна/біженці). Опис кожного кандидата в промпті скорочено до ~600 символів (`_shorten_for_filter()`, р. 1071; `FILTER_DESCRIPTION_CHARS`) — для перекладу стаття лишається повною. Відповідь `{keep, rejected[{id, entities_found, reason, detail}], updates}`. `reason` — **лише одна з 8 категорій** (`REJECTION_CATEGORIES`, R-12: Дубль, Вже публікувалось, Спорт, Реклама, Побут інших міст, Геоблок, Світовий шум, Не за тематикою), `detail` — коротке пояснення; у звіті — «Відхилено Gemini: N (Побут інших міст 5, …)», в `analytics.json` — `rejected_by_reason`. `updates` — ID з `keep`, які є суттєвим оновленням події з історії: новина отримує поле `is_update` у беклозі (при кожній фільтрації ставиться або знімається заново), а префікс `🔄 [ОНОВЛЕНО]: ` до заголовка додає код у `process_backlog()` (раніше вгадував перекладач). Перевірки: повтори ID, чужі ID, ID в обох списках або зовсім порожня відповідь → алерт і зупинка без змін беклогу («fail closed»). Кандидати, яких модель **не класифікувала**, лишаються в беклозі до наступного запуску (у звіті — «Gemini не класифікував»). У `DRY_RUN` — окремий звіт фільтра (`send_dry_run_filter_report()`, р. 1819).
4. Перші `BATCH_SIZE` = 3 погоджені → новинам без фото в RSS — фото зі сторінки статті (`og:image`/`twitter:image`, без webp/avif/svg і логотипів; `add_og_images()`, р. 679; зберігається в елементі беклогу) → пауза 15 с → `_build_translation_prompt()` (р. 1783, 12 правил перекладу) → `generate_news_texts_json()` (р. 1053) → чистка гомогліфів/наголосів/трикрапок. Якщо модель повернула «чужі» ID (бувало: число з URL статті замість `0`), `_remap_translation_ids()` (р. 908) зіставляє їх, коли це однозначно: одна новина в батчі → ID `0`; числа ≥ 100 зі шляху URL, що належать лише одній новині, → `_url_number_aliases()` (р. 927).
5. `validate_translation_strict()` (р. 1329): заголовок без HTML; у тексті лише `<b><i><u><s>`; повторна перевірка на спорт/рекламу; 2–3 хештеги, перший — латиницею (географія; діакритика прибирається: `#Korčula` → `#Korcula`, `_latinize_first_hashtag()`, р. 1314). Довший за 900 (з фото) / 2500 символів переклад **не відхиляється** — його обрізає `send_to_telegram()`. Трикрапки (`...`, `…`, `[…]`) прибирає `clean_generated_field()`.
6. Невдалий переклад → `record_translation_failure()` (р. 1300): `retry_after` = 1 год × N (макс. 6 год), після 5 спроб — алерт адміну (новина лишається в беклозі до 12 год віку).
7. Успіх → `send_to_telegram()` → запис URL і заголовка в історію → пауза 45 с між постами (після останнього — без паузи).
8. З беклогу прибираються лише опубліковані й відхилені фільтром; решта (зокрема некласифіковані) лишається.

### 2.3 Telegram: `send_to_telegram()` (р. 1520)
Пост = `<b>заголовок</b>` + текст + хештеги + `🔗 Джерело: <a>назва</a>`. Ліміт 1024 символи (з фото) / 4096 (без): якщо довше — HTML-безпечна обрізка тіла (`_truncate_html_visible()`, р. 1466) з приміткою «Повні деталі… 👇», хештеги зберігаються. Фото: 1 → `sendPhoto`, 2–10 → `sendMediaGroup`. Якщо Telegram відхилив фото (4xx) — повтор текстом; при 429/5xx — без фолбеку (результат невідомий, щоб не задублювати). Помилка HTML-розмітки → повтор без HTML. Ретраї `tenacity`: 4 спроби, `retry_after` від Telegram (до 120 с). Таймаут кожного запиту до Telegram API (пости, звіти, алерти) — 60 с (`TELEGRAM_TIMEOUT_SECONDS`).

### 2.4 Звіт адміну: `send_analytics_to_admin()` (р. 559)
Час виконання, помилки, повтори Gemini, воронка (переглянуто / уже відомі / відсіяно кодом з розбивкою за правилами / відхилено Gemini / не класифіковано Gemini), причини відхилення з сутностями, беклог по джерелах, опубліковано (з фото / текстом / український пріоритет / джерела), рядок «🤖 Моделі: фільтр — … | переклад — …» (фактичні моделі), «⛽ Квоту вичерпано» і «🧾 Спроби: 3.8-flash 503×2 | 3.6-flash ✅». Алерти `⚠️ ALARM` — `send_alert_to_admin()` (р. 472).

### 2.5 Тестовий запуск: `DRY_RUN` (р. 67, `_enter_dry_run_sandbox()` р. 2090)
Вмикається змінною `DRY_RUN=1`/`true` (у GitHub — галочка «Тестовий запуск»). Увесь цикл справжній: RSS, повний текст, фільтр і переклад Gemini, перевірки. Відмінності:
- на старті `feeds.json` і файли стану копіюються в тимчасову папку, і бот працює там → файли в репозиторії не змінюються (а workflow у тестовому запуску не комітить);
- пости йдуть в `ADMIN_CHAT_ID` (`_target_chat_id()`, р. 1515) з позначкою «🧪 ТЕСТ — не опубліковано в каналі»; пауза між постами 10 с замість 45;
- звіт адміну надсилається завжди, з позначкою «ТЕСТОВИЙ ЗАПУСК» і рядком «Підготовлено (тест, не опубліковано)»; алерти — з префіксом «🧪 DRY_RUN»;
- потрібні `TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEY`, `ADMIN_CHAT_ID`; `TELEGRAM_CHANNEL_ID` не потрібен.

## 3. Моделі Gemini і повтори (T-04)
Два окремі каскади (р. 106), як у молдовському боті. Змінюються без правки коду через GitHub Variables `GEMINI_FILTER_MODELS` / `GEMINI_TRANSLATE_MODELS` (назви через кому, у порядку пріоритету); якщо змінної немає — значення за замовчуванням:
- **фільтр:** `gemini-3-flash-preview` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` (з 31.10, T-21: 3.6-flash між preview і lite — preview тоді щоразу давала 503, і відбір робила lite; 3.6-flash ділить квоту з перекладом; lite — резерв з великою квотою);
- **переклад:** `gemini-3.8-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` (lite перекладає гірше, тому лише останній резерв).

**«Пам'ять» про недоступні моделі** (`apply_model_memory()` на старті `main()`, з 31.10, T-21): модель, яка в 2 останніх запусках за 3 год, де її пробували, не відповіла жодного разу (503 / таймаут / квота — з `model_attempts` в `analytics.json`), на цей запуск іде в кінець каскаду; коли вікно мине — знову на своєму місці. Каскад не скорочується. У звіті — «⏬ Відкладено в кінець каскаду».

`_generate_structured_response()` (р. 938) іде по каскаду:
- **429 / RESOURCE_EXHAUSTED** (квоту вичерпано) → модель одразу пропускається й до кінця запуску не викликається ні фільтром, ні перекладом (`EXHAUSTED_MODELS`);
- **швидка тимчасова помилка** (503 тощо) або **невідповідність ID** перекладу, яку не вдалося зіставити (`TranslationIdMismatch`) → ще одна спроба на тій самій моделі (пауза 3 с), потім наступна модель;
- **таймаут або 504 DEADLINE_EXCEEDED** (`is_slow_gemini_failure()`) → одразу наступна модель, без повтору (модель уже змусила чекати до 90 с);
- інші помилки → одразу наступна модель.

Таймаут одного запиту — 90 с (`GEMINI_TIMEOUT_MS`, р. 110; `HttpOptions` клієнта). Safety-фільтри вимкнені. `temperature`: фільтр 0.0, переклад 0.1. Відповідь валідується pydantic-схемою; для перекладу ще й збіг множини ID.
Кожна спроба пишеться в `stats["model_attempts"]`; звіт адміну показує, яка модель відповіла (`_models_line()`, р. 538), вичерпані квоти й усі спроби.

## 4. Дані (файли стану)
- Елемент беклогу: `title`, `description` (чистий текст), `url` (нормалізований, без `utm_*`, `fbclid`…), `image_urls[]`, `source`, `timestamp` (Unix, UTC), опційно `translation_failures`, `retry_after`, `last_translation_error`.
- `analytics.json` — масив із 100 останніх об'єктів статистики (з 30.10 додано `models_by_task`, `model_attempts`, `exhausted_models`; `models_used` — як раніше) (`_empty_stats()`, р. 2044). `timestamp` — UTC раннера.
- Запис атомарний (`.tmp` + `os.replace`); беклог читається з `.bak`, якщо основний файл пошкоджений, інакше бот зупиняється (а не обнуляє чергу).

## 6. CI: `.github/workflows/news_bot_run.yml`
- Тригер: лише `workflow_dispatch` (його викликає cron-job.org). Вхід `dry_run` (галочка «Тестовий запуск», за замовчуванням вимкнена) → `DRY_RUN` для бота; назва такого запуску в Actions — «🧪 DRY RUN (тестовий запуск)».
- `environment`: `production` для `main`, `staging` для інших гілок (секрети можуть відрізнятися).
- `permissions: contents: write` — для коміту стану.
- Змінні `GEMINI_FILTER_MODELS`, `GEMINI_TRANSLATE_MODELS` беруться з `vars.*` (Settings → Secrets and variables → Actions → Variables).
- `concurrency: croatia-news-bot-<гілка>`, `cancel-in-progress: false` — одночасно працює лише один запуск, наступний чекає. `timeout-minutes: 20`.
- Кроки: checkout@v5 → setup-python@v6 (3.11, кеш pip) → `pip install -r requirements.txt` → `python news_bot.py` (`id: bot`) → `git add` 4 файли стану → коміт `Update news history and backlog state [skip ci]` → `git pull --rebase` → `git push`.
- Окремий workflow `tests.yml` («Tests»): на кожен PR і вручну — `ruff check .` + `pytest -q`; без секретів, нічого не публікує.
- Крок коміту має `if: always() && steps.bot.outcome != 'skipped' && !inputs.dry_run` — стан зберігається й після падіння чи таймауту бота, щоб уже опубліковані пости не вийшли повторно.
